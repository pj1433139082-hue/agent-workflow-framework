# 协作总览

## 这是什么

协作底座负责跨业务通用能力：创建并定位任务、装载业务包、记录交互决定、续接任务、保存本地证据并生成导航索引。业务包负责场景自己的术语、阶段、检查规则和空白资料模板。

框架运行不等于业务系统运行。任务阶段只表示协作任务走到哪里，不表示订单、库存、支付、上架或外部平台的状态。

## 组件与责任

| 部分 | 维护什么 | 不代表什么 |
| --- | --- | --- |
| 协作底座 | 项目和任务身份、档位、命令、交互、续接、证据入口 | 某个行业系统 |
| 业务包 | 场景语言、阶段、可机检条件、人工决定、资料入口、空白模板 | 一份真实业务事实 |
| 项目工作区 | project.json、任务事实、本地证据和生成索引 | 框架分发仓库 |
| 任务状态索引 | 由任务事实和业务包规则导出的导航视图 | 第二份事实源或外部状态 |

真实项目工作区必须在框架仓库外。仓库只放通用代码、规则、模板和完全虚构的测试资料。

## 首版业务包

| 标识 | 场景 | 任务阶段 | 范围 |
| --- | --- | --- | --- |
| ecommerce-catalog | 电商商品资料审核 | collect → review → ready | ready 仅表示资料任务准备就绪，不表示商品已上架 |
| document-delivery | 通用文档交付 | draft → validate → complete | complete 仅表示本地文档任务完成，不表示已发给客户或外部平台 |

两套流程各自拥有阶段和检查规则，不能用一个业务包状态代替另一个。示例资料全部虚构；模板 payload 初始为空，使用者补入的内容才可能成为任务事实。

## 执行档位

档位是智能体协作节奏约定，不是 CLI 权限沙箱；它不扩展任务范围。档位随任务续接，不要求每次恢复时再选。任何 --apply 都是调用者明确发起的本地写入。

| 档位 | 行为 |
| --- | --- |
| full-auto | 自动执行确定性机检；遇到无法从证据推出的业务答案时停下询问，不猜测 |
| assisted | 需要业务选择时提出问题并记录回答；不会逐条命令索取审批 |
| manual-review | 在实质写入前暂停供人审核 |

所有档位使用相同的机检规则。真实退款、支付等外部动作不在首版范围内。

## 推荐读取顺序

1. 先看本页和 [快速开始](01-快速开始.md)。
2. 执行 doctor，并用 packs 确认当前可用的业务包。
3. 创建仓库外的任务工作区，按 task-id 读取 context 和 status。
4. 只有需要处理决定、续接或 hook 时，再看 [交互与续接](02-交互与续接.md) 和 [安全与事实源](../20-规则层/20-安全与事实源.md)。
5. 增加场景时看 [新增业务包](../10-流程层/10-新增业务包.md)。

## 关键原则

- 一个任务有稳定的 project-id、task-id 和 workflow 标识；恢复时显式定位任务，不猜任务。
- v0.1 的 new 在新项目工作区创建首个任务；没有向既有工作区追加任务的命令。
- v0.1 只支持线性阶段推进，不支持分支、回退或追加任务；需要不同业务动作时定义相应业务包，不复制 core。
- 原始事实保存在项目和任务文件及本地证据中；状态索引可重新生成。
- 交互决定是需要使用者回答的业务选择，不是自动检查结果，也不是永久操作许可。
- hook 只是只读上下文入口；客户端不触发时，AGENTS.md 与 CLI 命令仍可完成定位。
- 公开验收走 CLI 和只读 hook，见 [验收清单](../30-触发层/30-验收清单.md)。
