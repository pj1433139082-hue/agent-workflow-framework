# 快速开始

## 环境

- Python 3.11 或更高版本，只依赖标准库；不依赖 MLflow。
- 命令从框架仓库根目录运行。
- 项目工作区放在框架仓库之外；首版每个新工作区只创建一个项目和首个任务。
- 两个流程和下方资料都是合成演示，不要把样例当作真实业务规则。

主命令使用 python。Windows PowerShell 若 Python Launcher 指向 3.11，可将 python 替换为 py -3.11。先检查本机环境和可用业务包：

    python -m agent_workflow doctor
    python -m agent_workflow packs

## 流程一：电商商品资料审核

### 1. 创建外部工作区

在 PowerShell 中为演示创建一个新的临时工作区：

    $catalogWorkspace = Join-Path $env:TEMP ('agent-catalog-demo-' + [guid]::NewGuid().ToString('N'))
    python -m agent_workflow new $catalogWorkspace --project-id demo-catalog --workflow ecommerce-catalog --task-id catalog-review-001 --mode assisted --apply

new 创建 project.json、任务记录和模板文件。payload.json 为空值，review.md 含待填写提示。初始化成功不代表资料已审核。

### 2. 填入虚构商品资料

从 new 返回结果中复制 workspace 绝对路径。以下路径相对于该目录；用文本编辑器打开这两个文件：

    tasks\catalog-review-001\payload.json
    tasks\catalog-review-001\review.md

将 payload.json 全文替换为下面的合成数据，保留 JSON 格式：

    {
      "sku": "SYNTHETIC-001",
      "title": "虚构演示商品",
      "price": 19.9,
      "currency": "CNY",
      "synthetic": true
    }

将 review.md 全文替换为一份真实反映你对这份虚构数据检查结果的说明，例如：

    # 商品资料审核

    ## 检查结论

    本文件仅用于合成流程演示。示例字段满足此包的格式检查；不接真实商品，不代表商品已上架。

保存后运行 status：

    python -m agent_workflow status $catalogWorkspace --task-id catalog-review-001

collect 阶段要求 sku、title 为非空字符串，price 为大于 0 的数字，currency 为 CNY，synthetic 为 true。review.md 还不能含 TODO、TBD、待填写或待补充等模板标记。

### 3. 预览并进入 review

资料为空时运行 advance 会返回退出码 2 和缺少条件的信息，这是预期的阻塞结果：没有阶段推进，也不能称为成功预览。先根据 status 填完所需资料。

条件满足后，advance 默认只预览 collect → review：

    python -m agent_workflow advance $catalogWorkspace --task-id catalog-review-001

检查预览的 from_stage 和 to_stage，再显式写入阶段推进：

    python -m agent_workflow advance $catalogWorkspace --task-id catalog-review-001 --apply
    python -m agent_workflow status $catalogWorkspace --task-id catalog-review-001

### 4. 人工审阅并记录决定

在 review 阶段阅读 review.md。status/context 会列出当前问题 ID review-acceptance，选项为 accept 或 revise。只有审阅者确认示例结论准确时才回答 accept：

    python -m agent_workflow decision $catalogWorkspace --task-id catalog-review-001 --decision-id review-acceptance --answer accept --by demo-reviewer --apply

决定绑定回答时全部任务证据的摘要。之后不要修改 payload.json、review.md 或其他任务证据；任何证据变化都会使接受决定不再通过检查。若真实审阅结果应为 revise，就如实回答 revise，不要为推进阶段而接受。

### 5. 进入 ready 并核对状态

确认 review 检查通过后先预览，再推进：

    python -m agent_workflow advance $catalogWorkspace --task-id catalog-review-001
    python -m agent_workflow advance $catalogWorkspace --task-id catalog-review-001 --apply
    python -m agent_workflow status $catalogWorkspace --task-id catalog-review-001

预期本地状态为 evidence_valid: true、completed_locally: true。ready 只表示本地资料审核任务完成，不会发布或上架商品。

## 流程二：通用文档交付

### 1. 创建独立工作区

一个工作区只有一个任务，所以第二个流程要创建新的目录：

    $documentWorkspace = Join-Path $env:TEMP ('agent-document-demo-' + [guid]::NewGuid().ToString('N'))
    python -m agent_workflow new $documentWorkspace --project-id demo-document --workflow document-delivery --task-id local-document-001 --mode assisted --apply

### 2. 填写 payload 和 draft

在新文档工作区内打开并编辑以下相对路径：

    tasks\local-document-001\payload.json
    tasks\local-document-001\draft.md

payload.json 的虚构示例：

    {
      "audience": "虚构演示读者",
      "purpose": "本地流程验证",
      "synthetic": true
    }

draft.md 的虚构示例：

    # 虚构文档草稿

    这是一份用于检查协作流程的本地合成示例。

保存后查看检查结果并预览 draft → validate：

    python -m agent_workflow status $documentWorkspace --task-id local-document-001
    python -m agent_workflow advance $documentWorkspace --task-id local-document-001

确认预览后显式推进：

    python -m agent_workflow advance $documentWorkspace --task-id local-document-001 --apply

### 3. 填写 final，审阅后进入 complete

进入 validate 阶段后，在新文档工作区内打开并编辑：

    tasks\local-document-001\final.md

将模板提示替换为你确实审阅过的虚构终稿，例如：

    # 虚构交付文档

    这份内容仅供本地演示，不会发送或发布。

运行 status，阅读 final.md。只有确认内容符合本次本地演示目的后，回答当前阶段的 review-acceptance：

    python -m agent_workflow status $documentWorkspace --task-id local-document-001
    python -m agent_workflow decision $documentWorkspace --task-id local-document-001 --decision-id review-acceptance --answer accept --by demo-reviewer --apply
    python -m agent_workflow advance $documentWorkspace --task-id local-document-001
    python -m agent_workflow advance $documentWorkspace --task-id local-document-001 --apply
    python -m agent_workflow status $documentWorkspace --task-id local-document-001

终态只有在证据仍通过时才显示 evidence_valid: true、completed_locally: true。complete 仅表示本地文档任务完成，不会发送、发布或调用外部系统。

## 索引、版本与接管

context 默认读取任务资料；--write 显式生成或修复派生索引，--check 检查漂移：

    python -m agent_workflow context $catalogWorkspace --task-id catalog-review-001 --check
    python -m agent_workflow context $catalogWorkspace --task-id catalog-review-001 --write

不要手改 workflow-state.json。task.json 固定创建时完整业务包目录的摘要（workflow.json、SOP 等，忽略 Python 字节码缓存）；包内内容后续变化会让旧任务拒绝静默适配。首版没有迁移或回退命令；保留旧框架及资料，要用新流程时另建工作区并人工复核事实。终态证据被编辑后也要保留旧记录并另建工作区。

人工入口：`@AGENTS.md 阅读，接管这个任务：<业务包/工作区/任务ID>`

hook 和 doctor 只读。hook 需要 AGENT_WORKFLOW_WORKSPACE、AGENT_WORKFLOW_TASK_ID 显式定位；不会读取原始 prompt 或猜测任务。配置和客户端边界见[交互与续接](02-交互与续接.md)。
