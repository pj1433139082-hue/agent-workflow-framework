Architecture & Lifecycle Specification

通用智能体协作框架 · 全景分层架构与生命周期

面向人机协同与多智能体任务流转的确定性底座。坚持底座普适化、业务包插拔解耦、外部工作区物理隔离与不可跨阶段单向状态机，杜绝坏味道与幻觉操作。

核心设计亮点与架构原则

1. 工具环境与业务运行时绝对正交

框架工具要求的 Python ≥3.11 仅约束 CLI 工具自身，绝不强加给新创建的业务项目。业务项目可采用纯 Markdown、Node.js、Rust、Go 或专属 Python 版本，不预装无用环境。

ADR 0005

2. 交互三档位作为执行节奏约定

assisted、full-auto、manual-review 控制汇报频次与确认时机，并非文件系统沙箱。全自动档同样不得绕过确定性硬规则门禁，任何本地写入均由显式 --apply 触发。

ADR 0006

3. 任务恢复与证据双向核验回执

任务在长链协作中断重连时，通过 recovery-receipt.json 生成结构化核验回执。重新计算证据摘要并校验哈希，防止因环境抖动导致状态回退或误判。

ADR 0004

4. 配套启动技能与框架外工作区隔离

通过内置 project-start 配套技能调用公开 start CLI，将新项目安全构建在框架仓库之外，彻底避免业务真实数据对通用开源底座的污染。

ADR 0007

通用项目启动生命周期流转 (project-planning)

Stage 0: Kickoff

脚手架创建与初始握手 (start)

调用公开 start 命令生成项目工作区骨架、AGENTS.md 入口与首个规划任务；生成 business_environment 回执如实标明环境尚未配置。

Stage 1: Scope

范围与边界定义 (scope ──▶ plan)

将用户输入的目标、边界、排除项与成功标准持久化至 payload.json；机检确认必填范围完整后，推进至 plan 阶段。

Stage 2: Plan

方案设计与集中问卷 (plan ──▶ ready)

在 plan.md 中起草实施方案；将架构、环境、依赖选型等未决事项整合成 plan-acceptance 推荐问卷一次性向用户呈现，收集回答并写入 decisions.json。

Stage 3: Ready

启动就绪与无缝交接 (ready ──▶ handover)

所有机检项通过且必填决定关闭，状态达成 ready。若原交办目标已包含具体实现或部署，无缝继承执行档位继续开展业务，不打断重问。
