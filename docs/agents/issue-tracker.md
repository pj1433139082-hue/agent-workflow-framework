# 框架维护任务：GitHub Issues

本框架的规格与实施任务使用当前 checkout 的 `origin` 所对应 GitHub 仓库，通过 `gh` CLI 操作。先核对 origin，不能沿用其他工作区的仓库地址或依赖个人路径、访问令牌。

## 维护约定

- 规格保留为父 Issue；实施任务各有独立 Issue，并在正文引用父规格。
- 创建、读取、评论、标记与关闭使用 `gh issue`；读取任务同时查看正文、标签和评论。
- 任务依赖优先使用 GitHub 原生 issue dependencies；关系指向“本任务被哪些任务阻塞”。正文也写明 Blocked by 及真实 Issue 链接。
- 原生依赖不可用时用正文关系完整替代，不把平台可选能力设成实施门禁。
- 实施按真正可开始的任务推进，不为排列整齐制造依赖；已完成本地代码与测试不等于已推送或合并。
- 拆分任务时不修改或关闭父规格，也不以 PR 替代需求分流。
- 公网命令使用使用者当前的代理，仅对本次命令配置；不改变系统代理、VPN 或仓库权限，不写入认证凭据。

本页仅配置框架自身的维护协作。由框架生成的独立项目采用其自身的任务记录与后续维护安排，不自动绑定到本框架的 GitHub 仓库。
