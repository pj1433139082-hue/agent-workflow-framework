# 领域文档

本仓库采用单上下文布局：根目录一份 `CONTEXT.md` 维护跨业务的协作术语，`docs/adr/` 记录系统决策。

## 探索前先读

- 根目录 `CONTEXT.md`：使用其中的规范术语（协作底座、业务包、项目工作区、交办范围、执行档位等），不自造同义词。
- `docs/adr/`：只读与当前改动相关的决策。
- 当前改动与既有 ADR 冲突时显式指出，不静默覆盖，也不改写历史决策记录的时间口径。

这两处缺文件时按现状继续：不因为文件缺失中断工作，不主动新建空文件，也不把缺失当成需要立刻上报的故障。术语和决策在实际敲定时再补。

## 边界

`CONTEXT.md` 只维护领域词汇：名称、定义、边界和 `_Avoid_` 里被排除的说法。规格、实施计划和验收记录不写进词汇表——它们分别在当前 origin 的 GitHub Issues、任务的 plan.md 与 `docs/30-触发层/`。只有难以逆转、缺少背景会令人意外、且确实存在取舍的决策才进 `docs/adr/`。

真实业务事实不在本仓库：这里只收录通用代码、技能、模板、规则和完全虚构的测试资料。领域文档解释词语，不替代任务状态查询，也不构成任何外部操作的许可。
