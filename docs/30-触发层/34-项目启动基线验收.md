## 公开行为与源码技能

回归使用公开 CLI 子进程、只读 hook 和真实临时文件系统，不调用私有函数代替验收。覆盖默认预览零写入、默认 14 文件骨架、五类辅助文档单独/混合/重复选择、非默认任务标识导航、三个档位、规划证据与实际方案回答、决定失效、索引漂移、已有目录与非法/敏感输入拒绝。`project_files` 仍仅列项目入口和所选辅助文档，不包含引擎生成的项目事实和任务记录。

补充源码启动脚本演示：清空本次子进程的框架定位环境变量，在框架外临时目录执行源码技能脚本的 `--locate`，正确定位当前干净克隆；随后预览、创建一个合成项目，任务 ID 为 `kickoff-alpha`，只选择 environment 和 summary。预览没有创建目标；应用得到 16 文件，`project_files` 为 11 项。进入新项目后由本机定位文件续接，同一任务的 `context --check` 返回 `snapshot_matches=true`；未给出的范围信息仍为空，`can_advance=false`，没有把创建骨架报告成业务完成。

同一合成启动任务分别执行 `SessionStart` 和 `UserPromptSubmit` hook 子进程：只输出任务标识、流程、档位、阶段及最小导航，不提升项目名称、目标或原始内容。取消明确任务选择后不猜测目标。运行前后项目全部文件的路径与 SHA-256 相同。

以上仅证明 CLI/hook 子进程行为；未验证受信任 Codex 客户端实际触发，也不宣称全局技能安装已经完成。直接读取仓库内技能和入口即可使用此基线。

## 双轴代码审查

两名独立只读审查者分别核对规范与规格；没有阻塞项。Standards 轴没有书面规范违规，有 1 项低优先级判断建议：两份启动测试的 CLI/JSON 辅助逻辑重复，可在后续测试维护中复用，本票不为消除测试样板改动已经验收的行为。

Spec 轴没有可证实的实现错误，有 1 项低优先级范围提示：新增框架维护路由是否属于启动基线。保留该最小配置，是为了让维护者仅凭仓库定位已经采用的 GitHub Issues 和标签，也满足实施所用代码审查技能的仓库配置要求；不创建远端标签、不变更权限，不要求生成项目使用此跟踪器，不能作为业务门禁。
