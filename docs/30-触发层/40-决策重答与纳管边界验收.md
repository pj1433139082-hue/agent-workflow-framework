## 发现与修复

| 发现（修复前实测） | 处理 |
| --- | --- |
| `adopt --project-id new-id` 在已有 `project.json`（`project_id=old-id`）的工作区返回 `ok:true, applied:true`，随后 `status` 恒为 `task_identity_mismatch`，回执还建议执行同样会失败的索引修复 | 写入前校验身份，返回 `project_identity_mismatch` 并提示改用已有项目 ID |
| 已有 `.agent-workflow.local.json` 被无条件覆盖（`task_id` 从 `old-task` 改为 `kickoff`），且被列为 `created_files` | 逐字节保留并记入 `preserved_files`；新增 `local_marker` 回执字段（`file`/`preserved`/`active_task_id`） |
| `created_files` 未列出引擎写入的 `tasks/<id>/task.json`、`payload.json`、`plan.md` | 回执补齐任务记录 |
| 项目启动助手 `--locate` 只读当前目录的 `.agent-workflow.local.json`；在已纳管项目的子目录里（本机登记不可用时）返回 `framework_location_error`，而只读 hook 已能向上定位 | 助手改为与 hook 相同的向上探测，遇 Git 根停止 |
| 环境探测缺 .NET/C++/PHP/Ruby/Dart/Swift/Elixir | 扩展根级模式与 `*.sln`/`*.csproj`/`*.fsproj`/`*.vbproj` 后缀识别 |
