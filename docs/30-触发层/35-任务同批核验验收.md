## 可复现的缺陷与回归

2026-10-04，先以公开 status 子进程复现旧版：在读取 review.md 前受控修改已经读过的 payload.json，将有效价格改为负值。旧版仍返回 catalog-fields.passed=true，而来源摘要来自变化后的资料。此测试先失败，再由新核验批次修复。

测试侧 tests/support/observe_cli.py 使用 CPython 的 open 审计事件，在真实文件读入前通知父进程并等待其修改合成资料。它运行公开模块 CLI 或只读 hook，不导入私有函数、不 patch 内部实现、不向生产添加测试开关；判断不依赖某个内部函数名或精确打开次数。同步有超时，失败会清理测试拥有的子进程。

tests/test_verification.py 覆盖：

- 中途资料改动后不拼接旧检查和新摘要。
- context 核验期间的档位/下一步变化与新增证据成员能被重新核验，旧决定失效。
- 持续编辑时有限停止，返回 materials_changed；context --write 不产生索引或事实写入，不重放业务操作。
- 稳定 status/context 的共同视图一致，hook 仅输出导航，不提升正文、答案或原始提示词；全部项目文件字节不变。
- 索引缺失、损坏、漂移的只读发现及显式修复，修复不回写事实；根目录辅助文档不扩大任务证据，任务目录新增证据仍使决定失效。
- 完整业务包的 SOP 改动阻止静默适配，既有 Python 缓存排除规则保持不变。
- CRLF 文本沿用原来的通用换行处理，跨行字面检查不误判；来源与决定摘要仍绑定原始字节。该兼容回归也先失败后修复。

核验在返回前复核文件 SHA-256 和目录成员，而不只靠时间戳；大文件按流计算摘要，超限文本不会作为有效正文。本保护不是跨文件原子快照，也不能排除观察间改动后又恢复或最终复核后的修改，见规则层说明。
