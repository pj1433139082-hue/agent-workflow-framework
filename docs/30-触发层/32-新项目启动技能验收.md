## 测试契约

六项新增公开 CLI 测试覆盖：预览和创建的文件/状态契约；档位和任务 ID 续接；scope → plan → ready 与真实 `plan-acceptance` 回答；修改计划后旧接受失效；现存目标和不安全路径/ID 拒绝；名称和目标中的明显凭据拒绝且不回显；五种空白/不完整/伪正文方案即使得到 accept 仍被阻止推进。十二项原有测试全部回归通过。

方案检查要求四个指定二级章节各有非标题正文，排除注释及代码示例；这只证明结构存在，不证明内容正确或适合项目，仍需结合实际资料接受方案。

新项目真实资料只进入项目工作区。`start` 不覆盖已有目录、不初始化 Git、不创建远端、不部署；空白业务字段不是业务事实。`ready` 是启动规划的本地终态，不是业务实现完成。

首次使用中发现 scope 字段补全入口和“骨架创建成功”的含义不够直观，已在一键启动指南中补明：根据实际回答编辑 payload.json，再查 status；不重复 start，也没有独立 scope 子命令。
