# 任务写入与恢复验收

## 范围

对应 [#4：统一任务写入与索引共锁，保留部分完成和非重放恢复](https://github.com/pj1433139082-hue/agent-workflow-framework/issues/4)，审查基点为 #3 完成提交 `0e823ed8d72b357297de26245d9ddf43dbe2bc1b`。交付版本以包含本记录的提交为准；本票不实现 #5 的已有项目辅助文档补建或 #6 的整体冷启动验收。

同一任务的三个事实写入入口与独立索引重建共享锁域。默认预览、status、只读 context 和 hook 不抢写锁或写文件。业务阶段、三档节奏、schema 1.0 与证据范围保持不变，不新增审批轮次或真实业务写入。创建工作区的独占占位/部分创建保留仍独立，不为代码去重把 new 并入既有任务写入。

## 复现与公开边界

2026-10-05，以真实临时工作区和公开 CLI 子进程先复现四个缺口，分别失败后修复：

- 已占用任务锁时，context --write 原先仍能写索引。
- task-plan 已提交后，锁目录被外部占用使解锁失败，原先返回通用失败。
- 原子替换成功后，暂存清理路径被外部重新占用，原先将已提交计划报为未提交。
- 事实已提交后的索引核验遇到外部损坏的字段类型，原先被顶层通用错误报为整个动作失败。

统一准入的整合审查另发现一处误门槛，也以公开回归先失败后修复：超限正文原先阻挡有效当前回答/计划。现在只将其正文检查判为失败，并保留 invalid_text 诊断；回答/计划可记录，advance 仍因内容未通过而拒绝推进，unsafe_path 等安全错误仍停止。

Spec 子审查追加指出共享原子写入对创建流程的边缘影响。公开 new 回归证实：初始暂存清理失败时原先忽略清理结果并继续搬运未知残留。现创建生命周期独立检查清理状态，在占位发布前停止，保留待检查暂存，不搬运或递归删除未知替代内容；不把新建并入既有任务共锁协议。

测试 tests/test_task_writes.py 只走公开 CLI、只读 hook 和真实文件。tests/support/observe_cli.py 使用 CPython 文件审计事件通知测试父进程，在 OS 读取/替换/清理前协调合成资料；不导入或 patch 私有函数、不增加生产注入开关，不断言内部调用顺序或精确打开次数。暂停与子进程都有超时，测试只处置其自己创建的文件、权限和进程。

## 已覆盖的故障和恢复

| 场景 | 公开结果与保留内容 |
| --- | --- |
| 先预览，后改成非法证据；或抢锁前修改必要条件 | 根据锁内当前资料拒绝提交，保留外部更新，阶段不额外推进 |
| 回答期间改证据、成员、档位/下一步 | 整批重新核验，回答绑定当前证据，保留其余更新 |
| 一个任务写入持锁，其他事实写入/索引重建竞争 | 立即 task_busy；竞争方不提交；原调用只推进自己的合法一步 |
| context --write 持锁，计划更新竞争 | 同样 task_busy；较新的后续写入生成自己的索引，不被旧视图覆盖 |
| 事实替换目标发生目录类型冲突或真实 OS 拒绝 | operation=not_completed，原事实与索引保持；可能的遗留锁另行提示检查 |
| 三个事实入口分别在提交后遇到索引目标目录冲突 | operation=completed、local_record=incomplete、repeat_operation=false；原事实保留 |
| 按同目标 context 修复 | 不重放阶段、回答或计划；context --check 匹配，来源摘要对应已提交的 task.json |
| 清理时锁非空、身份被替换、暂存清理被阻挡 | 保留完成回执和未知路径，提示检查，不递归清理或诱导重放 |
| 索引重建自身完成后解锁失败 | 仍报告该索引操作完成，事实字节不变 |
| 空模板或超限正文的内容检查尚未通过 | 有效当前回答/计划仍可记录；advance 仍执行累计条件 |

访问限制用真实 OS 权限演示：Windows 将替换目标设为只读；POSIX 暂时移除测试任务目录写权限，结束后恢复测试拥有的权限。目录类型冲突、锁占用与清理阻挡也均由真实文件系统执行，不以模拟异常代替。来源摘要断言针对公开索引对应的实际文件字节；不是通过私有实现计算期望值。

共锁只协调遵守同一协议的框架写入，不锁住任意编辑器或恶意程序。核验是有界变化检测，不是多文件原子快照；事实和索引也不是跨文件事务。无可靠回执的进程中断仍需先核对事实。锁/暂存身份检查不能保证消除检查与 OS 删除间的恶意替换竞争。
