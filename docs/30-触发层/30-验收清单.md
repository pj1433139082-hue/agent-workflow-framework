# 验收清单

本文是可执行验收清单，不是已通过声明。每次验收记录命令结果、运行环境和临时工作区位置；没有对应输出或证据的项目保持未确认。

## 自动化验收

从仓库根目录运行：

    python -m unittest discover -s tests -v

Windows 可用 py -3.11 -m unittest discover -s tests -v。测试应通过公开 CLI 验证任务创建、状态读取、上下文、阶段预览/推进和失败输入；只读 hook 应验证不写入任务事实。不要以私有函数测试代替公开入口验收。

本页不预填通过结果。应将实际运行结果记录在本次交付证据中。

## 临时工作区验收

使用一个仓库外、此前不存在的临时目录，不使用真实业务资料：

    $workspace = Join-Path $env:TEMP ('agent-workflow-acceptance-' + [guid]::NewGuid().ToString('N'))
    py -3.11 -m agent_workflow doctor
    py -3.11 -m agent_workflow packs
    py -3.11 -m agent_workflow new $workspace --project-id fake-project --workflow ecommerce-catalog --task-id fake-catalog-001 --mode assisted --apply
    py -3.11 -m agent_workflow status $workspace --task-id fake-catalog-001
    py -3.11 -m agent_workflow context $workspace --task-id fake-catalog-001
    py -3.11 -m agent_workflow advance $workspace --task-id fake-catalog-001

核对 advance 默认只预览。确认该项没有改变当前任务阶段后，再用 --apply 进行一次推进，并记录其检查结果。按实际可执行范围另建 document-delivery 任务，确认其阶段属于 draft → validate → complete。

编辑任一已通过阶段使用的任务证据，再运行 status，确认旧阶段检查会重新执行；已接受的决定也应因全部任务证据摘要变化而不再通过。对缺失、过期或无效的 workflow-state.json，先用 context --check 观察，再用 context --write 重建派生索引。

## hook 验收

在当前 PowerShell 会话中显式定位临时任务，再运行两个只读事件入口：

    $env:AGENT_WORKFLOW_WORKSPACE = $workspace
    $env:AGENT_WORKFLOW_TASK_ID = 'fake-catalog-001'
    python scripts/context_hook.py --event SessionStart
    python scripts/context_hook.py --event UserPromptSubmit

确认 stdout 为官方 hookSpecificOutput 格式、只含只读导航，且不包含原始 prompt；比较调用前后的任务事实文件，确认 hook 没有写入。清除会话变量后再次运行，确认缺少显式定位时不会猜测其他任务：

    Remove-Item Env:AGENT_WORKFLOW_WORKSPACE
    Remove-Item Env:AGENT_WORKFLOW_TASK_ID
    python scripts/context_hook.py --event SessionStart

配置位于 .codex/hooks.json，采用仓库根目录脚本定位和 commandWindows。仓库提供 hook 配置不等于客户端已触发。若要证明客户端集成，需要在信任该仓库的受支持客户端中记录实际触发证据；不得仅据配置文件写“已触发”。见[官方 hooks 文档](https://learn.chatgpt.com/docs/hooks)。

## 安全和边界检查

- [ ] 项目工作区路径在仓库之外。
- [ ] 初始 payload 为空，没有把模板字段解释为已确认业务事实。
- [ ] task.json 固定完整业务包目录（workflow.json、SOP 等，忽略 Python 字节码缓存）的 pack_digest；包内容变化不会让旧任务静默适配。
- [ ] 已通过阶段仍受 status 检查；证据变化会使旧接受决定失效。
- [ ] 每任务 workflow-state.json 来自 CLI 派生，未被手工当作事实源。
- [ ] 机器路径、永久远端许可未写入状态索引。
- [ ] hook 和 doctor 只读；hook 不猜任务。
- [ ] 没有真实系统调用，退款、支付、上架等外部动作仍未实现。
- [ ] 两个虚构流程的阶段和范围没有混用。
