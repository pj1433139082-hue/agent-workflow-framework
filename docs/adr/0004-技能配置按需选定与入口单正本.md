# ADR 0004：技能配置按需选定与入口单正本

新项目需要 `docs/agents/` 下的标签词汇、领域文档读取顺序和任务落点，否则要求“发布到 issue tracker”的技能没有去处。但任务落点有两种同样正当的形式：GitHub Issues 与仓库内本地 Markdown。对本机五个既有仓库的对照显示，已配置任务落点的四个里两种各占两个，第五个尚未配置，没有一种能当默认值。因此 `triage-labels.md` 与 `domain.md` 进必选文件，`issue-tracker.md` 由 start 的 `--tracker` 选定；未选定时不生成该文件，回执如实报告未选定，之后用 `project-docs --tracker` 补建。

CLAUDE.md 只在这五个仓库中的一个里存在，且那一份是 AGENTS.md 的全文镜像——同一套指令有两处正本，必然漂移。因此 CLAUDE.md 不进必选文件，而是可选文档，内容只有一行指向 AGENTS.md 的指针，镜像式复制被明确禁止。

代价是接管者要多看一个字段才知道任务落在哪里，也不能靠“文件都在”推断 tracker 已选定；`project-docs` 的 `--with-docs` 不再是唯一入口，改为 `--with-docs` 与 `--tracker` 至少提供一项。收益是新项目不会继承一个从未被选定的任务落点，也不会多出第二份入口正本。

## 本轮落地范围

2026-10-09，使用者在对照五个仓库的入口文档后确认以下范围；这是已接受的设计，不是实现或测试通过记录：

- 项目模板新增 `docs/agents/triage-labels.md`、`docs/agents/domain.md`（必选），以及两份 issue-tracker 变体模板，由 `--tracker github|local` 选定其一。
- `CONTEXT.md` 模板从空壳改为术语写法约定，不含任何业务术语。
- 框架本体补自己的 `docs/agents/domain.md`，并在 AGENTS.md 指向它。
- CLAUDE.md 作为可选文档，只生成指针。这一项由 #16 落地；决策在此一并记录，避免同一取舍分两处写。

不迁移或覆盖既有项目；`learn-model-framework` 缺 `docs/agents/` 属另一个仓库，另立任务，不挂本决策。不改写 31–39 号历史验收记录里的文件数与时间口径，必选文件数变化记在新的验收记录里。不新增业务包，不改 project-planning 的阶段、检查或决定契约，也不把任何仓库的私人工具链写进模板。

## 边界示例

- “开个新项目”：未选 tracker 时生成 triage-labels 与 domain，不生成 issue-tracker.md，回执报告未选定。
- “开项目，任务记在 GitHub”：`--tracker github`，只生成对应那一份，不混入本地 Markdown 约定。
- “给已有项目补任务落点”：`project-docs --tracker local`；已存在 issue-tracker.md 时报告 preserved，不覆盖。
- “让另一个客户端读到同一套指令”：这是 #16 落地后的行为——`--with-docs claude` 只生成一行指向 AGENTS.md 的指针，不把正文复制过去。本决策记录时该取值尚未实现，当前传入会被参数校验拒绝。
