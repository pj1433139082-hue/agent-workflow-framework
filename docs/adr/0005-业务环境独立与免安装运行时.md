# ADR 0005：业务环境独立与免安装运行时

## 背景

通用协作底座应当服务于任意技术栈的业务项目（包括纯文档、Node.js、Go、Rust、Java 或特定 Python 版本的系统）。早期若将框架工具本身的执行环境（Python >=3.11）与业务项目的环境耦合，容易导致智能体在接入新项目时，强制为不需要 Python 的项目创建虚拟环境，或试图修改宿主机的全局环境与代理配置。

## 决定

1. **工具环境与业务环境严格正交**：框架 CLI 工具的兼容声明（`requires-python = ">=3.11"`）仅用于约束框架解释器自身，不作为业务项目的技术选型要求。
2. **免安装与纯文档项目友好**：对于纯文档或静态项目，不强制安装业务运行时，不预设包管理器，也不在启动时进行全局依赖探测。
3. **环境契约按需沉淀**：
   - 业务环境选型、依赖版本与测试入口统一记录在任务方案（`plan.md`）；
   - 实际环境配置与核验结果按需记录在项目辅助文档 `docs/project/environment.md`（通过 `--with-docs environment` 启用）；
   - 框架不增加第二套独立环境配置或审批流。
4. **禁止隐式操作与虚假验证**：`doctor` 仅体检框架工具健康度；`start` 命令返回的 `business_environment` 回执如实标明本次未配置、未验证业务环境，严禁以骨架创建成功冒充项目可运行。禁止擅自更改系统代理、VPN 或全局环境变量。

## 取舍

放弃“一键式自动拉起业务环境”的魔法式封装，换取底座对任意业务场景的最大化普适性与零环境污染风险。真实环境配置必须由调用者在明确交办的前提下按项目说明显式执行。

## 后果

- 框架不会因外部项目缺少特定 Python 解释器而阻断协作规划。
- 业务项目的技术自由度得到完全保障，环境事实清晰记录在工作区文档内。
