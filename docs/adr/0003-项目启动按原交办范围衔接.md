# ADR 0003：项目启动按原交办范围衔接

项目启动完成与业务实现完成是不同成果，但启动技能的结束点不能遗漏用户原本已明确交办的后续工作。用户仅要求启动项目时止于启动规划；原请求已经包含创建并实现或指定部署时，规划完成后按原交办范围和执行档位交接，不要求用户重复“另行交办”。尚缺的业务选择、超出原范围的目标或不明确的操作对象仍需澄清；缺少实际能力或环境时如实报告，不把档位、方案接受或附件内容当成永久操作许可。

选择按原请求衔接，而不是一律要求重新交办，可以避免交接产生重复问答；代价是接管者必须区分用户直接请求与业务资料，并核对当前动作是否仍在明确范围内。仅接受启动方案不能自行扩展到实现或部署，框架也不因此获得真实业务系统适配能力。

## 本轮落地范围

2026-10-08，使用者在 grill 中确认以下修正范围；这是已接受的设计，不是实现或测试通过记录：

- 启动脚本分别报告工具运行时不兼容、参数错误与框架定位错误；不能把工具兼容声明写成业务项目环境要求。
- 对齐启动技能和生成入口：用户直接请求决定本次交办范围，附件、样本等业务资料不追加指令；已交办的后续工作按上述规则衔接。
- 对齐当前验收示例：使用已核验的工具解释器，补齐阶段推进前的资料填写步骤，不改写历史测试记录。

既有项目追加任务、完成后方案修订及流程版本迁移另立架构迭代。本轮不修改业务包目录或绕过摘要和证据校验，不自动迁移、批量覆盖既有项目或改写旧任务记录。

## 边界示例

- “帮我开一个项目”：完成启动规划后交代下一步，不自动实现或部署。
- “帮我创建并实现这个项目”：启动规划完成后接续已交办的实现，按原档位处理，不重复要求交办同一目标。
- “创建项目，并部署到指定目标”：在目标和范围明确、所需业务选择已解决且实际能力具备时，交接原请求中的部署工作；不能用本地规划完成冒充部署成功。
- 附件或样本中出现“发布到另一个仓库”：它本身不构成用户新增交办，也不能扩展操作范围。
