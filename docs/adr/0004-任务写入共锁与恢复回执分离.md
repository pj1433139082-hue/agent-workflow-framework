# ADR 0004：任务写入共锁与恢复回执分离

## 背景

在多会话或智能体自动化推进任务时，任务事实（`task.json`、`payload.json`、`decisions.json`）与派生索引（`workflow-state.json`）需要保证一致性。若将所有写入绑定为单一大事务，一旦事实写入成功但派生索引写入或锁清理遭遇文件系统临时 I/O 阻塞，若向调用方返回通用失败退出码，自动化调用者容易重放原命令（如重复调用 `advance` 或 `decision`），从而引发状态机非法跃变、阶段重复推进或数据覆盖。

## 决定

1. **事实落盘与派生索引分级**：任务核心事实落盘成功即认定操作逻辑已完成；派生索引与辅助记录作为次级产物，与事实写入共锁，但写入失败不倒推事实未完成。
2. **结构化恢复回执 (Recovery Receipt)**：当事实已提交但派生索引或锁清理异常时，系统返回包含事实完成标记、非零退出码与明确 `recovery` 命令的结构化回执。
3. **禁止盲目重放**：调用方（包含自动化脚本与子智能体）严禁重放原 `new`、`advance`、`decision` 或 `task-plan` 命令；必须直接执行回执中提供的唯一 `context <工作区> --task-id <ID> --write` 索引重建指令。
4. **锁争用防护**：文件锁遭遇争用时返回 `task_busy`，不隐式排队阻塞、不推断前次结果，避免死锁或竞态破坏。

## 取舍

出具恢复回执需要框架在错误捕获链路中保留部分成功信息，并要求调用方解析结构化错误模型；但它杜绝了分布式/多智能体环境下最危险的重放漏洞与事实双写漂移。

## 后果

- 事实源变更具有原子不可逆性，状态推进安全可追溯。
- 自动化智能体可基于 `recovery` 字段安全自愈，不产生不可控副作用。
- 派生索引随时可经单条 context 指令幂等重建。
