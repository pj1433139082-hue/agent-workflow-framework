# ADR 0010：上下文 Hook 的零配置就地探测

## 背景

当前只读 Codex / IDE Hook（`scripts/context_hook.py`）强依赖会话前显式配置的环境变量 `AGENT_WORKFLOW_WORKSPACE` 与 `AGENT_WORKFLOW_TASK_ID`。在大部分实际终端、桌面 IDE 或智能体启动流程中，使用者通常通过命令行 `cd` 直接进入项目目录，不会专门预置环境变量。导致 Hook 频繁退化为“未选定任务”，丧失了自动为智能体注入任务状态与最小文档指针的能力。

## 决定

1. **自适应向上递归探测机制**：
   - Hook 优先读取显式环境变量（若已设置，保持向后兼容）；
   - 若环境变量未配置，自当前工作目录（`Path.cwd()`）向上逐级检索父目录（直至文件系统根或 Git 根目录）；
   - 检索标志性项目元数据：`.agent-workflow.local.json` 与 `project.json`。
2. **局部元数据驱动的任务绑定**：
   - 若找到 `.agent-workflow.local.json`，直接提取其中声明的 `task_id` 与项目根路径；
   - 若未声明特定 `task_id` 但存在 `tasks/` 目录：若仅有唯一任务则自动绑定该任务；若存在多个任务则按最近修改或聚焦任务推导，或优雅降级为提示一次性定位；
   - 严格只读调用 `engine.context()`，生成包含阶段、阻塞决定与最小文档列表的标准导航结构。
3. **会话级防抖与静默降级**：
   - 当探测失败或项目任务尚有歧义时，输出一次性的标准定位建议，并记录防抖缓存，避免在每个提问事件中刷屏或抛出未捕获异常；
   - Hook 保持严格只读与轻量执行（<500ms），绝不执行写入、不阻塞调用者。

## 取舍

Hook 引入了目录树嗅探逻辑，相比纯读环境变量增加了微量的磁盘 I/O（仅限几层父目录判断）。但彻底消除了对繁琐环境变量的依赖，实现了真正的开箱即用。

## 后果

- 使用者只要进入任意由框架创建或纳管的项目目录，智能体便能立即无感获得当前任务的全局上下文与最小文档指引；
- 极大地降低了多项目切换时的认知负担。
