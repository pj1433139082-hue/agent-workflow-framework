# ADR 0012：纳管保留项目身份与本机导航标记

## 背景

`adopt` 把已有目录接入协作框架。此前有两个边界会破坏「非破坏性」承诺：

- 工作区已有 `project.json` 且其 `project_id` 与本次 `--project-id` 不同时，`adopt` 仍报告成功并写入任务事实；此后每条命令都以 `task_identity_mismatch` 失败，工作区事实上不可用，而回执还引导使用者去做索引修复。
- 已存在的 `.agent-workflow.local.json` 会被无条件覆盖。它是零配置导航的唯一指针；在已纳管工作区新增任务时覆盖它，等于把当前会话的目标悄悄改到新任务。

## 决定

1. 既有 `project.json` 的 `project_id` 与本次参数不一致时，`adopt` 在写入前以 `project_identity_mismatch` 拒绝，并提示改用已有项目 ID 或更换工作区。
2. 已存在的 `.agent-workflow.local.json` 逐字节保留，只在其缺失时生成；它出现在 `preserved_files` 而不是 `created_files`。
3. 回执新增 `local_marker`：标记文件、是否保留、当前指向的 task-id。
4. `created_files` 补上引擎实际写入的任务记录（`task.json`、`payload.json`、`plan.md`），让回执与实际写入一致。

## 取舍

- 在已有工作区新增任务不会自动切换零配置导航；要切换时由使用者显式改写标记或用 `AGENT_WORKFLOW_TASK_ID` / `--task-id` 指定。显式优于隐式。
- `start` 不受影响：它只创建尚不存在的工作区，仍然生成标记。

## 后果

- 文档 `docs/00-入口层/03-一键启动新项目.md` 记录三个回执字段与身份一致性规则；`docs/20-规则层/20-安全与事实源.md` 与验收清单同步「工作区可以有多个任务，但追加任务不是新增阶段」。
- 回归覆盖：身份冲突零写入、标记保留、新增任务不移动指针、任务记录出现在回执中。
- 本决定取代 ADR 0002 中「v0.1 无追加任务命令」的表述：`adopt --task-id` 可以在既有工作区新建任务，但它不新增阶段、不改变线性推进。
