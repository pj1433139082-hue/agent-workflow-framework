# ADR 0011：旧阶段决定在证据变化后可重答

## 背景

任务按线性阶段推进，每条接受的业务决定绑定回答当时全部任务证据的摘要。只要证据文件被编辑，原答案就不再满足检查，`status` 会把这条旧阶段决定重新列为未决项。

旧行为下这条路径是死路：`decision` 只接受当前阶段定义的问题，而任务不会回退阶段。使用者唯一的选择是放弃当前工作区、另建一个重新审查，等于因为一次资料修订丢掉全部任务连续性；但多数情况下需要修订的只是证据，业务选择本身并没有改变。

## 决定

1. `decision` 接受两类问题：当前阶段定义的决定，以及**此前已经记录过答案**的旧阶段决定。
2. 重答同一条旧阶段决定只把 `evidence_digest` 重新绑定到当前证据，并记录新的 `by`；不推进阶段、不回退阶段，也不改变交互档位。
3. 从未记录过答案的旧阶段决定不能被补答。允许补答等于让当前阶段越过一个从未执行过的检查，仍按 `invalid_decision` 拒绝。
4. 检查语义不变：`status` 仍重检当前及此前所有阶段，证据再变时会再次失效，可以再次重答。

## 取舍

- 牺牲了「答案只写一次」的简单历史模型，换取证据漂移后的可修复性；task.json 只保留最新答案，被覆盖的旧答案不留历史（`by` 只标出最新回答者）。
- 重答不改变业务结论：如果修订改变的是业务选择本身而不是证据，仍应在新工作区重新审查并保留原记录，不能靠重答覆盖结论。
- 没有放宽阶段门禁：补答未记录过的决定仍然被拒绝，旧阶段检查依旧参与 `can_advance`。

## 后果

- `docs/00-入口层/02-交互与续接.md`、`docs/20-规则层/20-安全与事实源.md` 与验收清单同步改为「已记录的决定可重答、未记录的决定不可补答」。
- 回归覆盖两条边界：旧阶段证据失效后可重答并恢复通过且阶段不变；伪装阶段回退仍不能补答从未记录的决定。
