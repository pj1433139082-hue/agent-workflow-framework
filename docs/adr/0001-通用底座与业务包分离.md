# ADR 0001：通用底座与业务包分离

- 状态：已接受
- 日期：2026-10-03

## 背景

协作任务需要稳定的身份定位、交互、续接和证据管理。不同业务又有各自的阶段、术语、检查规则和资料结构。把两者混在一起会让通用入口依赖某个场景；每个场景复制整套框架则会让通用能力分散维护。

## 决定

维护一个通用协作底座，并以可替换业务包描述具体场景。底座提供共同任务与 CLI 契约；每个业务包独立定义自己的术语、任务阶段、检查规则、资料入口和空白模板。

v0.1 只提供完全虚构的 ecommerce-catalog 与 document-delivery 两个流程，用于证明该边界可以运行。底座与样例不连接真实业务系统。

## 取舍

这让底座不必理解每个行业的流程，也避免每个业务包重建一套任务续接能力；代价是新增场景必须遵守统一接口，并维护自己的阶段和检查契约。首版不引入动态执行插件，以控制扩展面和运行时行为。

## 后果

- 业务包的状态机可以不同，不能强制用一个通用业务状态替代。
- 通用功能的变更不应悄悄增加某个业务包的事实或权限。
- 新包通过公开 CLI 和只读 hook 验收，不以复制框架仓库扩展。
