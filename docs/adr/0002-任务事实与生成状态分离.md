# ADR 0002：任务事实与生成状态分离

- 状态：已接受
- 日期：2026-10-03

## 背景

跨会话续接需要易于查看的任务阶段和检查结果，但如果把该导航结果当作事实保存，事实修改后就可能留下互相矛盾的两份状态。自动续接也不能靠机器猜当前任务或把绝对路径和远端许可固化在索引里。

## 决定

项目与任务事实分别保存在仓库外的 project.json、tasks/{task-id}/task.json、payload.json 和本地证据中。每任务 workflow-state.json 是从这些事实和业务包检查结果派生的导航索引，不手工维护；用 context --write 生成，以 context --check 检查漂移。索引不包含机器路径或永久远端许可。

task.json 固定创建时完整业务包目录的 pack_digest；包内规则或 SOP 改变时，旧任务拒绝静默适配。每条已接受的决定也保存回答当时全部任务证据的 evidence_digest；证据改变后，该决定不再通过检查。status 重检当前及之前阶段的条件。

续接必须显式提供项目工作区和 task-id。hook 只从当前会话环境变量 AGENT_WORKFLOW_WORKSPACE、AGENT_WORKFLOW_TASK_ID 定位任务，不使用仓库全局指针，也不猜测任务。运行时输出框架绝对文档指针。

## 取舍

派生索引可以重建并减少双事实源漂移，但调用方必须运行 CLI 更新或检查索引。显式定位需要会话配置，却能避免恢复到错误任务。

## 后果

- task.json、payload.json 和本地证据拥有原始业务事实。
- workflow-state.json 可丢弃后重建，不应被人工编辑成权威记录。
- context --write 可重建缺失、漂移或无效的派生索引，不回写任务事实或绕过机检。
- pack_digest 固定流程版本；v0.1 无迁移、回退或追加任务命令。旧阶段或终态证据需要修订时，保留原记录并在新工作区重新审查。
- hook 与 doctor 是只读辅助；客户端未触发时，AGENTS.md 和公开 CLI 是兜底入口。
