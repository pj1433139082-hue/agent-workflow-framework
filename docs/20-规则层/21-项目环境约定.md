# 项目环境约定

通用框架规定如何选择、记录和核验环境，不为所有业务项目预设语言、最低版本或统一环境。项目确定选型后，按该项目自身依赖和目标平台约束实现可复现运行。环境选择并入现有启动方案确认，不增加审批轮或阶段。

## 分开三种环境

| 环境 | 要求与事实来源 | 边界 |
| --- | --- | --- |
| 框架工具 | 所选工具实现的自身依赖声明；本仓库 Python CLI 对应 pyproject.toml | 兼容条件只约束这个工具，不作为架构规范或业务环境要求 |
| 业务开发与运行 | 当前项目需求、已有配置及 tasks/<task-id>/plan.md | 每个项目独立选择；可使用其他 Python 版本或其他语言 |
| 测试与交付目标 | 当前项目的目标平台和兼容要求 | 只在相关时约定操作系统、架构、容器、驱动等，不从开发机推断目标环境 |

调用框架时使用已核验的框架 Python 解释器；运行业务程序时使用该项目自己的解释器或启动入口。不要因为当前终端激活了业务虚拟环境，就把其中的 python 当成兼容的框架工具。

当前 CLI 仍是 Python 实现，具有自身的兼容条件；环境中立指项目规范不预设统一技术栈，不表示任何工具可以在任意运行时执行。只为所选工具核验其兼容环境，不因此要求业务项目安装同一语言、重建环境或更改系统默认解释器。具体工具要求见框架 README 和依赖声明，不在生成的项目规则中抄一份固定版本。

## 按项目需要选择

可运行项目在 plan.md 的“技术选择”和“验收方法”中约定业务环境；需要实际配置或运行检查时，按需生成 docs/project/environment.md。纯文档或资料整理项目可以记录“不适用”，不强制安装运行时或生成环境文档。

技术方案未定时写明“待确定”、依据和下一步，不从项目名称猜版本，也不将框架 Python 版本、演示业务包或其他项目环境当作默认业务要求。已有明确要求直接沿用；仍需用户决定的选项与其他方案缺项集中到原 plan-acceptance 问题，不逐个依赖再问一轮。

计划中按实际需要写明：业务语言及版本约束、开发/交付平台、环境隔离方式、依赖管理与锁定文件、安装/启动/测试入口。只有适用的项才写；不要求每个项目补齐容器、GPU、数据库或网络配置。凭据只记录变量名和获取方式，不写实际值。

## 选择不等于验证

plan.md 保存要求和选型理由；environment.md 引用该方案，记录实际检查结果，不另抄一份环境要求或维护第二套状态 JSON。

实际核验按项目范围检查解释器/运行时版本、隔离位置、依赖安装与锁定情况、启动入口和代表性测试。每项写清核验命令、实际结果、证据位置及核验时间，并区分“通过 / 失败 / 未执行 / 不适用”；缺少命令或无法运行就明确未执行，不能用模板内容补成成功。

配置和运行检查属于后续实际实现任务；scope → plan → ready 仍只覆盖启动规划。没有安装依赖不阻止规划完成，但不能据此宣称业务程序已可运行。业务交付验收按该项目真实需求验证，不把一套固定的环境检查强加到所有项目。

## 配置与续接边界

用户交办实际开发或环境配置时，先检查已有依赖文件、版本要求、运行入口和当前解释器，再在项目隔离环境内按要求配置。对不熟悉的安装/启动脚本先检查内容与作用，不因它存在于项目中就自动执行。

不更改系统默认 Python、全局 PATH、系统代理或 VPN 来适配单个项目；不升级或覆盖其他项目环境。需改变共享系统设置或新增超出任务范围的服务时，先说明影响并请求具体方向。依赖安装权限与外部操作范围不由“自动档位”或规划接受代替。

续接时从项目 AGENTS.md、任务 context/status 和 plan.md 恢复已选环境；确有环境工作时再读 environment.md 和真实依赖配置。文档缺失可用 project-docs 补模板，已有文件保留。模板生成、框架自检、业务配置、业务运行验证分别报告。

## 公开命令的回执

doctor 只检查框架工具，返回 runtime_scope=framework_tools_only、business_runtime_constraint=null、business_runtime_checked=false。它不探测或安装业务环境。

start 只创建项目骨架。其 business_environment 回执给出 policy=per_project、方案路径、按需环境文档路径，并明确 configured_by_start=false、verified_by_start=false。未选环境文档时 verification_file=null；这些值只描述该命令的工作，不代表项目后来仍未配置或验证。

已有项目的 project-docs 同样只补辅助模板，不安装依赖，不改变任务阶段，也不替代实际核验。
