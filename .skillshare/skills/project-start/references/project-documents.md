# 按需项目文档

新项目默认保持轻量骨架。用户确实需要环境检查、多模块设计、长期进展、里程碑总结或结果定稿时，读取本文；不以“项目开始”为由补齐一套空卡。

## 吸收的职责与事实源

| 原项目卡职责 | 通用框架中的位置 | 何时独立成文档 |
| --- | --- | --- |
| 概述、目标、范围、成功标准 | tasks/<task-id>/payload.json；项目入口只导航 | 默认已有，不另抄一份概述事实 |
| 实施计划、选型、风险、验收 | 同一任务 plan.md；重大新决定另存 ADR | 默认已有，不重复建计划卡 |
| 技术栈、运行环境 | plan.md 声明选型；environment.md 记录实际核验 | 有运行时、依赖或部署环境需要检查 |
| 架构与数据流 | architecture.md 链接模块/接口及既有决定 | 实际复杂度值得独立说明 |
| 进度与交接 | task.json/context 是当前状态；progress.md 是事件记录 | 长期或多阶段工作、里程碑及阻塞 |
| 总结 | summary.md；初始为 draft，无完成日期 | 真实里程碑、交接或项目结束时 |
| 官方结果与实验台账 | results.md 给出条件、证据和实际采用理由；领域台账由业务包定义 | 多版本、路线冲突或研究任务需要；不固定某个指标 |

## 选择和生成

向 start 添加可重复参数 `--with-docs environment|architecture|progress|summary|results`，例如 `--with-docs environment --with-docs progress`。所选文档生成在 docs/project/，使用同一模板实例化和路径保护；默认预览不写入，应用只创建选择的辅助文件。重复选择会去重，仍使用原任务 ID、档位和 project-planning 流程。

选择由已说明的项目需求决定，并与名称、目录和目标在同轮说明；没有需求则使用最小默认。不为每张辅助卡另设确认轮。

项目创建之后按需补文档时，直接从定位到的框架 `templates/project/docs/project/<名称>.md.tmpl` 读取模板，用实际 task-id 替换占位符，再以正常文件编辑创建所需文档。已有文件先阅读并保留内容；不重复 start，不为了套模板新建或覆盖整个工作区。

辅助文档不是第二套阶段状态，也不自动进入 kickoff 的机检契约。需用于正式验收的实际证据，按相应业务包明确存放与核验；总结核实真实证据后再写结论。总结完成与项目完成分开报告，不为生成骨架或空模板写完成日期。

## 通用边界

模板不依赖 Obsidian、Templater、个人 Vault、固定水/材料方向或 ML 指标。不自动复制旧仓历史、缓存、运行产物或凭据。既有项目接入、档案归集与全新项目创建是不同操作；start 只用于不存在的新目录。
