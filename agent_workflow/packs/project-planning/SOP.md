# 通用新项目启动

适用于电商、文档、软件或其他新项目的需求与计划准备，不套用模型实验室阶段或演示业务规则。

1. scope：只保存用户已说明的目标、使用者、范围和成功标准；不能推断的信息集中询问后填入 payload.json。用户说本轮没有排除事项时，可明确记录“当前无另行排除事项”，不能假装已有答案。
2. plan：根据已明确的范围编写 plan.md，保留“可执行任务”“技术选择”“风险”“验收方法”四个二级章节，每节填写实际正文，不以标题、注释、代码示例或占位符代替方案。机检只核对结构和非空，内容是否适合项目仍需人工核对。提出 plan-acceptance 的推荐与备选，按用户实际回答记录，不因选择自动档位就默认接受。
3. ready：仅表示启动方案已准备好且证据有效。业务实现、多个开发任务、部署、外部系统操作另按实际需求组织；当前线性 kickoff 任务不是整个业务系统状态机。

使用原生 status/context/advance/decision。业务输入和计划仅放在项目工作区，不回传框架仓库。新项目根 AGENTS.md 指向自己的任务和分层文档；框架 CLI 从源码 checkout 调用，目标业务技术栈不受工具 Python 版本限制。
